01

Orientation

There is no component called “tab”. What reads as a tab is a thread row — one <li> inside the sidebar’s <ul role="list" class="flex flex-col gap-px">. Every row is rendered by a single component, SidebarV2Row, which takes 20 props and has two layout variants.

Variant Height Used for Trailing action Source
card 78 px (h-[4.875rem]) The live inbox — every thread that isn’t snoozed or settled Snooze + Settle SidebarV2.tsx:843-986
slim 36 px (h-9) The Snoozed and Settled shelves Wake / Un-settle SidebarV2.tsx:733-838

How a row picks its variant

The parent partitions threads into three sections and the variant follows mechanically: const isCard = section === "active".

Density is earned, not inferred. Settled and snoozed are the only things that collapse a row — the sidebar never second-guesses what still matters. Everything else stays a full card. SidebarV2.tsx:2377-2382

One surface model

All rows share rowSurfaceClassName. Live threads used to render as elevated cards while settled threads were plain rows, which gave neither a useful hierarchy nor a reliable hover cue. Now status lives in the row content and surface is reserved for interaction — hover, multi-select, route. SidebarV2.tsx:652-669

No icon-rail state to design. The sidebar is collapsible="offcanvas" — the whole panel slides away rather than shrinking to icons, so there is deliberately no mini/collapsed tab treatment. AppSidebarLayout.tsx:165-183
Focus has no visible ring. The row is a <div role="button" tabIndex={0}> whose surface class sets outline-none with no focus-visible: replacement — unlike Sidebar V1, which carries focus-visible:ring-1 focus-visible:ring-inset ring-ring. Keyboard focus is currently invisible on a V2 row. Flagging it as a design gap, not documenting it as intent. SidebarV2.tsx:657 vs Sidebar.logic.ts:368

          04

          State specimens

          Every specimen is a real row: hover it. Cards marked forced also have the state pinned on so you can see it without a pointer. live means it animates.

          These stack, they don’t replace. A row simultaneously has a run status, an attention flag, a surface state, and a set of content flags. That’s why §05 gives you a playground — the interesting cases are combinations.

          Run status

          resolveSidebarV2Status — mutually exclusive, evaluated top-down. Hues follow the system-wide convention set by Sidebar V1 and the mobile Live Activity/widgets, so a thread reads the same colour everywhere it surfaces. Sidebar.logic.ts:411-425 · SidebarV2.tsx:447-485

          Attention layer

          Only reachable when the status resolved to ready: the status ternary falls through to isWoke, then isUnread, then the plain relative time. Woke beats Done.

          Surface & interaction

          These compose on top of any status. isActive (the routed thread) wins over isSelected (multi-select), which wins over recede and in-flight dimming.

          Content flags

          Each is independently present or absent on any row.

          Capability gates

          On environments whose server predates thread.settle / thread.snooze, the affordances hide entirely rather than fail on click. Snooze is additionally hidden on work that is blocked on you or has a queued turn, because the server rejects both. SidebarV2.tsx:361-365, 633-644

              Container states

              Rows live in one flat <ul>: the live inbox first, then the Snoozed shelf, then Settled. Shelf headers are the only chrome between them.

              Light — full sidebar list

              Container state Behaviour Source
              Snoozed shelf Sits between the inbox and Settled — out of the way, never gone. Header renders whenever anything is snoozed; rows only when expanded. Collapsed by default. Vanishes entirely at count 0. Blue label + blue hairline rule. SidebarV2.tsx:1491, 2455-2487
              Settled shelf Expanded by default. Muted label and border-coloured rule. Collapsing it still keeps the routed thread visible — navigating into a settled thread must never hide it. SidebarV2.tsx:1476-1486, 2488-2515
              Collapsed header Label becomes Snoozed (n) / Settled (n) — the count is the shelf’s entire footprint when collapsed. Chevron un-rotates. SidebarV2.tsx:2471, 2499
              Settled tail paging First 10 settled rows render; Show 25 more pages the rest. Recent history is the common lookup, so the deep tail stays behind an explicit click. The open thread is never hidden under it. SidebarV2.tsx:159-160, 1454-1475, 2518-2531
              Empty When all three sections are empty: a centred prompt, branching on whether any projects exist at all. SidebarV2.tsx:2534-2545
              List reflow AutoAnimate, {duration: 150, easing: "ease-out"}. Rows are keyed `${threadKey}:${variant}` on purpose: when a thread settles the card fades out in place and the slim row fades in at its settled position, instead of one element FLIP-sliding through every row in between. Rows are translucent, so a crossing row would read as text painted over text. SidebarV2.tsx:2183-2186, 2368, 2385-2391

              Right-click menu

              A native context menu, not a DOM popover — so there is no hover/open styling on the row itself when it’s up. Items, in order, all capability- and state-gated: New thread on {branch} · Settle/Un-settle thread · Snooze ▸ (4 presets: in 1 hour, this evening, tomorrow, next week) or Wake thread · Rename thread · Mark unread · Delete (destructive). SidebarV2.tsx:1985-2021

              Hover tooltip

              Every row is a tooltip trigger — glass popup, side="right" align="start", 150 ms delay. Shows title, project, environment, branch, a branch-mismatch warning (“You’re currently checked out on another branch.”), model, and the session’s last error in red. SidebarV2.tsx:215-301, 2362-2367

              State matrix

              Derived predicates — the whole logic in five lines

              Predicate Definition Source
              status hasPendingApprovals → "approval" · hasPendingUserInput → "input" · session.status ∈ {running, starting} → "working" · session.status === "error" → "failed" · else "ready" Sidebar.logic.ts:411-425
              isUnread latestTurn.completedAt > lastVisitedAt — never-visited counts as read, so flipping the beta flag doesn’t light up every historical thread. Sidebar.logic.ts:223-232
              isWoke wokeAt !== null && (lastVisitedAt === null || lastVisitedAt < wokeAt) — unlike Done, a never-visited woke thread does show the pill: snoozing is an explicit act. A corrupt visit timestamp counts as never-visited rather than eating the wake signal. SidebarV2.tsx:431-433
              isInFlight status ∈ {working, approval, input} SidebarV2.tsx:441
              shouldRecede (status === "ready" || isInFlight) && !isUnread && !isWoke && !isActive && !isSelected — note failed is excluded, so a failed row never recedes. SidebarV2.tsx:442-443
              showSnoozeButton snoozeSupported && canSnooze(thread, {now}), with a derived snoozeMenuOpen so a stale true can’t permanently pin the hover actions if the button unmounts while the popover is up. SidebarV2.tsx:631-644
